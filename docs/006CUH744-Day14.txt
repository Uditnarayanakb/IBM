TASK 1: WHAT DO YOU UNDERSTAND ABOUT GIT COLLABORATION?
======================================================================

Git Collaboration is the process where multiple developers work on the
same project simultaneously using Git as the version control system.

Key Points:
-------------
1. Multiple team members can work on different features at the same time.
2. Changes are tracked and recorded through commits.
3. Developers share code using remote repositories such as GitHub,
   GitLab, or Azure Repos.
4. Branches are used to isolate work and avoid conflicts.
5. Changes are merged into the main branch after review and testing.
6. Collaboration ensures code consistency, traceability, and teamwork.

ASCII Representation:
---------------------

      Developer A
            |
            v
      +-----------+
      | Feature A |
      +-----------+
            |
            |
            v

+----------------------------------+
|          GIT REPOSITORY          |
+----------------------------------+

            ^
            |
            |
      +-----------+
      | Feature B |
      +-----------+
            ^
            |
      Developer B


Outcome:
---------
All team members contribute safely while maintaining a single source
of truth for the project.

TASK 3: COMMANDS USED WHILE COLLABORATING IN GIT
======================================================================

Common Collaboration Commands:
------------------------------

1. Clone Repository

   git clone <repository_url>

   Purpose:
   Downloads a remote repository to local machine.

------------------------------------------------------

2. Check Status

   git status

   Purpose:
   Shows modified, staged, and untracked files.

------------------------------------------------------

3. Create Branch

   git branch feature-branch

   Purpose:
   Creates a new branch.

------------------------------------------------------

4. Switch Branch

   git checkout feature-branch

   OR

   git switch feature-branch

------------------------------------------------------

5. Pull Latest Changes

   git pull origin main

   Purpose:
   Fetches and merges latest changes from remote.

------------------------------------------------------

6. Add Files

   git add .

   Purpose:
   Stages files for commit.

------------------------------------------------------

7. Commit Changes

   git commit -m "Added new feature"

   Purpose:
   Saves changes locally.

------------------------------------------------------

8. Push Changes

   git push origin feature-branch

   Purpose:
   Uploads commits to remote repository.

------------------------------------------------------

9. Fetch Remote Changes

   git fetch

   Purpose:
   Downloads latest information without merging.

------------------------------------------------------

10. Merge Branch

    git merge feature-branch

    Purpose:
    Combines changes from one branch into another.

------------------------------------------------------

11. View Log

    git log

    Purpose:
    Displays commit history.

------------------------------------------------------

12. Resolve Conflicts

    git status

    Purpose:
    Identifies conflicted files during merge.

TASK 5: DAILY BEST PRACTICES FOR WORKING WITH GIT REPOSITORIES
======================================================================

1. Pull latest changes before starting work.

   git pull origin main

------------------------------------------------------

2. Create a separate branch for every feature or bug fix.

   feature/login-page
   bugfix/header-alignment

------------------------------------------------------

3. Write meaningful commit messages.

   GOOD:
   git commit -m "Add login validation"

   BAD:
   git commit -m "changes"

------------------------------------------------------

4. Commit frequently.

   Small commits are easier to review and revert.

------------------------------------------------------

5. Push work regularly.

   Prevents local data loss.

------------------------------------------------------

6. Resolve conflicts immediately.

   Do not postpone conflict resolution.

------------------------------------------------------

7. Review code before merging.

   Ensure quality and consistency.

------------------------------------------------------

8. Delete unused branches.

   Keeps repository clean.

------------------------------------------------------

9. Avoid committing sensitive information.

   Examples:
   - Passwords
   - API Keys
   - Secrets

------------------------------------------------------

10. Keep main branch stable.

    Only merge tested and reviewed code.

TASK 11: CREATE A CLASS WITH ACCESS MODIFIERS
======================================================================

Access Modifiers in TypeScript:
-------------------------------

1. public
   - Accessible from anywhere.

2. private
   - Accessible only within the same class.

3. protected
   - Accessible within the class and its child classes.

======================================================================
EXAMPLE PROGRAM
======================================================================

class Employee {

    public empId: number;
    private salary: number;
    protected department: string;

    constructor(
        empId: number,
        salary: number,
        department: string
    ) {
        this.empId = empId;
        this.salary = salary;
        this.department = department;
    }

    public displayEmployee(): void {
        console.log("Employee ID: " + this.empId);
        console.log("Salary: " + this.salary);
        console.log("Department: " + this.department);
    }
}

class Manager extends Employee {

    public showDepartment(): void {
        console.log("Department: " + this.department);
    }
}

let emp = new Employee(101, 50000, "IT");

console.log(emp.empId);      // Accessible

emp.displayEmployee();

let mgr = new Manager(102, 80000, "HR");

mgr.showDepartment();


======================================================================
OUTPUT
======================================================================

101

Employee ID: 101
Salary: 50000
Department: IT

Department: HR

======================================================================
ACCESS MODIFIER VISIBILITY
======================================================================

                 +------------------+
                 |    Employee      |
                 +------------------+
                 | public empId     |
                 | private salary   |
                 | protected dept   |
                 +------------------+
                          |
                          |
                          v
                 +------------------+
                 |    Manager       |
                 +------------------+
                 | Can access       |
                 | empId            |
                 | department       |
                 +------------------+

======================================================================
ACCESS TABLE
======================================================================

public
  |
  +--> Class
  +--> Child Class
  +--> Outside Class

private
  |
  +--> Class Only

protected
  |
  +--> Class
  +--> Child Class

======================================================================
KEY POINTS
======================================================================

✓ public  -> Accessible everywhere.

✓ private -> Accessible only inside the class.

✓ protected -> Accessible inside the class and
               inherited child classes.

✓ private members cannot be accessed directly
  outside the class.

✓ protected members support inheritance while
  maintaining encapsulation.

TASK 14: WHAT ARE TYPE ANNOTATIONS IN TYPESCRIPT?
======================================================================

Definition:
-----------

Type Annotations are used to explicitly specify the data type of a
variable, parameter, function return value, or object property.

They help TypeScript understand what type of data is expected and
provide type checking during compilation.

Syntax:
--------

variableName: dataType

Example:
---------

let studentName: string = "John";
let age: number = 25;
let isActive: boolean = true;

======================================================================
EXAMPLE
======================================================================

let course: string = "TypeScript";
let duration: number = 30;

console.log(course);
console.log(duration);

Output:
--------

TypeScript
30

======================================================================
ASCII REPRESENTATION
======================================================================

        Variable
            |
            v

     course: string

     age: number

     isActive: boolean

            |
            v

     Type Safety


Benefits:
----------

✓ Detects errors during compilation
✓ Improves code readability
✓ Better IntelliSense support
✓ Makes code easier to maintain

======================================================================
SHORT ANSWER
======================================================================

Type annotations are used to define the expected data type of variables,
parameters, properties, and return values in TypeScript, enabling type
safety and error detection during development.

TASK 15: WHAT IS THE PURPOSE OF THE "ANY" KEYWORD IN TYPESCRIPT?
======================================================================

Definition:
-----------

The "any" type allows a variable to store any kind of value without
type checking.

TypeScript disables type checking for variables declared with "any".

Example:
----------

let value: any;

value = "Hello";
value = 100;
value = true;

console.log(value);

Output:
--------

true

======================================================================
ASCII REPRESENTATION
======================================================================

            any
             |
    +--------+--------+
    |        |        |
    v        v        v

 string   number   boolean

             |
             v

    Accepts Everything

======================================================================
WHEN TO USE ANY?
======================================================================

✓ When the type is unknown.
✓ While migrating JavaScript code to TypeScript.
✓ When handling dynamic data.

Disadvantages:
---------------

✗ No type safety
✗ Runtime errors may occur
✗ Less compiler support

======================================================================
SHORT ANSWER
======================================================================

The "any" keyword allows a variable to hold values of any data type and
disables TypeScript's type checking for that variable.

TASK 16: DIFFERENCE BETWEEN "ANY" AND "UNKNOWN"
======================================================================

Definition:
-----------

Both "any" and "unknown" can store values of any type.

However:

any
----
No type checking.

unknown
---------
Type checking is required before using the value.

======================================================================
EXAMPLE USING ANY
======================================================================

let data: any = "Hello";

console.log(data.toUpperCase());

Output:
--------

HELLO

No compiler error.

======================================================================
EXAMPLE USING UNKNOWN
======================================================================

let data: unknown = "Hello";

if (typeof data === "string") {
    console.log(data.toUpperCase());
}

Output:
--------

HELLO

Type checking is mandatory.

======================================================================
ASCII REPRESENTATION
======================================================================

                 Any
                  |
                  v

      "Trust me, I know the type"

                  |
                  v

      No Validation Required


------------------------------------------------------


               Unknown
                  |
                  v

     "Verify the type first"

                  |
                  v

         Type Check Needed

======================================================================
COMPARISON
======================================================================

any
 |
 +--> Stores any value
 +--> No type checking
 +--> Unsafe

unknown
 |
 +--> Stores any value
 +--> Requires type checking
 +--> Safer

======================================================================
ASCII TABLE
======================================================================

                +----------------+----------------+
                |      any       |    unknown     |
+---------------+----------------+----------------+
| Any Value     |      YES       |      YES       |
| Type Safety   |      NO        |      YES       |
| Verification  |  Not Required  |   Required     |
| Safe Usage    |      LOW       |      HIGH      |
+---------------+----------------+----------------+

======================================================================
SHORT ANSWER
======================================================================

The "any" type bypasses all type checking, whereas "unknown" also
accepts any value but requires type validation before its usage, making
it safer than "any".

TASK 17: WHAT IS THE tsconfig.json FILE USED FOR?
======================================================================

Definition:
-----------

tsconfig.json is the configuration file used by the TypeScript compiler.

It defines how TypeScript files should be compiled into JavaScript.

When a project grows larger, tsconfig.json helps maintain consistent
compiler settings across the entire application.

======================================================================
SAMPLE tsconfig.json
======================================================================

{
  "compilerOptions": {
    "target": "ES2020",
    "module": "commonjs",
    "strict": true,
    "outDir": "./dist"
  }
}

======================================================================
COMMON OPTIONS
======================================================================

target
-------
Specifies JavaScript version.

Example:
"target": "ES2020"

------------------------------------------------------

module
-------
Specifies module system.

Example:
"module": "commonjs"

------------------------------------------------------

strict
-------
Enables strict type checking.

Example:
"strict": true

------------------------------------------------------

outDir
-------
Specifies output folder for JavaScript files.

Example:
"outDir": "./dist"

======================================================================
ASCII REPRESENTATION
======================================================================

             tsconfig.json
                    |
    +---------------+---------------+
    |               |               |
    v               v               v

   target         module         strict

                    |
                    v

         TypeScript Compiler
                 (tsc)
                    |
                    v

          Generates JavaScript

======================================================================
PROJECT FLOW
======================================================================

      TypeScript Files
              |
              v

      +------------------+
      | tsconfig.json    |
      | Compiler Rules   |
      +------------------+
              |
              v

            tsc
              |
              v

       JavaScript Files

======================================================================
SHORT ANSWER
======================================================================

The tsconfig.json file is the TypeScript configuration file that
specifies compiler settings such as target JavaScript version, module
system, strict type checking rules, and output directories for the
entire project.
