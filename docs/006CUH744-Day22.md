## Task 1: What are Stereotype Annotations?

### First, Why Do We Need Stereotype Annotations?

In Spring, classes are managed as:

```text
Beans
```

Question:

```text
How Does Spring Knowm

Which Classes Should Be Managed
As Beans?
```

Answer:

```text
Stereotype Annotations
```

Spring scans the application and automatically registers classes marked with stereotype annotations as Spring Beans.

---

### What Are Stereotype Annotations?

Stereotype annotations are special Spring annotations used to identify the role of a class inside an application and allow Spring to automatically detect and manage it.

---

### Common Stereotype Annotations

```text
@Component

@Service

@Repository

@Controller
```

All of these are specializations of:

```text
@Component
```

---

### Why Are They Important?

They help Spring understand:

```text
Which Class Is A Controller

Which Class Contains Business Logic

Which Class Talks To Database

Which Class Is A General Component
```

---

### Typical Layered Architecture

```text
Client

↓

Controller

↓

Service

↓

Repository

↓

Database
```

Each layer uses an appropriate stereotype annotation.

---

### Key Idea

```text
Stereotype Annotations

↓

Tell Spring

What Role A Class Plays

↓

Automatically Create Beans
```

---

## Task 2: What all Stereotype Annotations have you used till now in Spring? Can you explain with an example?

### 1. @Component

Used for:

```text
Generic Spring Bean
```

When the class does not belong specifically to:

```text
Controller

Service

Repository
```

---

#### Example

```java
@Component
public class EmailUtil {

    public void sendEmail() {

        System.out.println("Email Sent");

    }

}
```

---

### 2. @Service

Used for:

```text
Business Logic Layer
```

---

#### Example

```java
@Service
public class UserService {

    public String getUser() {

        return "Alice";

    }

}
```

---

### Why @Service?

```text
Validation

Calculations

Business Rules

Processing Logic
```

usually belongs here.

---

### 3. @Repository

Used for:

```text
Database Access Layer
```

---

#### Example

```java
@Repository
public class UserRepository {

    public User findUser() {

        return new User();

    }

}
```

---

### Why @Repository?

Responsible for:

```text
Insert

Update

Delete

Fetch Data
```

from database.

---

### 4. @Controller

Used in:

```text
Spring MVC
```

to handle:

```text
HTTP Requests
```

---

#### Example

```java
@Controller
public class HomeController {

    @GetMapping("/")
    public String home() {

        return "home";

    }

}
```

---

### Typical Application Flow

```text
Browser

↓

@Controller

↓

@Service

↓

@Repository

↓

Database
```

---

### Example From Real Projects

```java
@Controller
public class EmployeeController {
}

@Service
public class EmployeeService {
}

@Repository
public class EmployeeRepository {
}
```

---

### Key Idea

```text
@Controller
------------
Handles Requests

@Service
---------
Business Logic

@Repository
------------
Database Operations

@Component
-----------
Generic Spring Bean
```

## Task 3: You have used JDBC connection in Spring Framework. Can you give some key concepts of JDBC connection?

### First, What Is JDBC?

JDBC stands for:

```text
Java Database Connectivity
```

It is the standard Java API used to connect Java applications to relational databases.

---

### JDBC Architecture

```text
Java Application

↓

JDBC API

↓

Database Driver

↓

Database
```

---

### Key JDBC Concepts

#### 1. Driver

Database-specific driver.

Examples:

```text
MySQL Driver

Oracle Driver

PostgreSQL Driver
```

---

#### 2. Connection

Represents connection between:

```text
Java Application

↓

Database
```

Example:

```java
Connection con =
    DriverManager.getConnection(
        url,
        username,
        password
    );
```

---

#### 3. Statement

Used to execute SQL queries.

Example:

```java
Statement stmt =
    con.createStatement();
```

---

#### 4. PreparedStatement

Most commonly used.

Advantages:

```text
Safer

Faster

Prevents SQL Injection
```

Example:

```java
PreparedStatement ps =
    con.prepareStatement(
        "select * from users where id=?"
    );
```

---

#### 5. ResultSet

Stores data returned from database.

Example:

```java
ResultSet rs =
    ps.executeQuery();
```

---

#### 6. executeQuery()

Used for:

```text
SELECT
```

queries.

---

#### 7. executeUpdate()

Used for:

```text
INSERT

UPDATE

DELETE
```

queries.

---

#### 8. Closing Resources

Always close:

```text
Connection

Statement

ResultSet
```

to avoid memory leaks.

---

### JDBC Flow

```text
Load Driver

↓

Create Connection

↓

Create Statement

↓

Execute Query

↓

Process ResultSet

↓

Close Resources
```

---

### Key Idea

```text
JDBC

↓

Connects Java Applications

↓

To Relational Databases
```

---

## Task 4: When you are modernising an application what are the best practices that you need to follow while working on Spring JDBC?

### First, What Does Modernisation Mean?

Modernisation means:

```text
Improving Existing Applications

Without Breaking Existing Functionality
```

especially when working with:

```text
Legacy JDBC Code
```

---

### Best Practice 1

#### Use JdbcTemplate

Avoid:

```java
Manual JDBC Code
```

such as:

```text
Connection

Statement

ResultSet

Manual Closing
```

Use:

```java
JdbcTemplate
```

because Spring manages repetitive JDBC operations automatically.

---

### Best Practice 2

#### Use PreparedStatement

Avoid:

```java
String sql =
    "select * from users where id="
    + id;
```

Use:

```java
PreparedStatement
```

or parameterized queries.

Benefits:

```text
Security

Performance

SQL Injection Prevention
```

---

### Best Practice 3

#### Externalize Database Configuration

Avoid hardcoding:

```java
username

password

url
```

Use:

```properties
application.properties
```

Example:

```properties
spring.datasource.url=
spring.datasource.username=
spring.datasource.password=
```

---

### Best Practice 4

#### Connection Pooling

Use:

```text
HikariCP
```

or another connection pool.

Benefits:

```text
Better Performance

Reduced Connection Creation Cost

Improved Scalability
```

---

### Best Practice 5

#### Proper Exception Handling

Avoid:

```java
catch(Exception e)
```

Use proper logging and meaningful exception handling.

---

### Best Practice 6

#### Keep SQL Separate

Avoid putting large SQL queries inside:

```text
Controller

Service
```

classes.

Preferred structure:

```text
Controller

↓

Service

↓

Repository

↓

Database
```

---

### Best Practice 7

#### Follow Layered Architecture

```text
@Controller

↓

@Service

↓

@Repository

↓

Database
```

Never place database logic directly inside controllers.

---

### Best Practice 8

#### Use Transactions

For multiple related database operations use:

```java
@Transactional
```

to maintain consistency.

---

### Modern Spring JDBC Flow

```text
Controller

↓

Service

↓

Repository

↓

JdbcTemplate

↓

Database
```

---
<a id="spring-integration-with-hibernate-and-jpa"></a>

## Task 5: How does Spring integrate with Hibernate or JPA, and what benefits does this bring?

### First, What Problem Are We Trying To Solve?

Suppose we need to:

```text
Save Data

Read Data

Update Data

Delete Data
```

from a database.

One option is:

```text
JDBC
```

But with JDBC we write:

```text
Connections

PreparedStatements

ResultSets

Manual Mapping
```

again and again.

ORM frameworks like Hibernate were introduced to reduce this work.

---

### What Is JPA?

JPA stands for:

```text
Java Persistence API
```

It is a specification that defines how Java objects should be mapped to database tables.

Think of JPA as:

```text
Rules And Interfaces
```

---

### What Is Hibernate?

Hibernate is:

```text
An Implementation Of JPA
```

It follows the JPA specification and provides the actual implementation. 

---

### Where Does Spring Come In?

Spring integrates with JPA and Hibernate and manages:

```text
Bean Creation

Dependency Injection

Transactions

Database Configuration
```

for us.

---

### Architecture

```text
Controller

↓

Service

↓

Repository

↓

Spring Data JPA

↓

Hibernate

↓

Database
```

---

### Example

#### Entity

```java
@Entity
public class Employee {

    @Id
    private Long id;

    private String name;

}
```

---

#### Repository

```java
@Repository
public interface EmployeeRepository
        extends JpaRepository<Employee, Long> {
}
```

---

#### Service

```java
@Service
public class EmployeeService {

    @Autowired
    private EmployeeRepository repository;

    public List<Employee> getEmployees() {

        return repository.findAll();

    }

}
```

---

### What Happens Internally?

```text
findAll()

↓

Spring Data JPA

↓

Hibernate

↓

SQL Query Generated

↓

Database

↓

Result Returned
```

---

### Benefits Of Spring + Hibernate/JPA

#### 1. Less Boilerplate Code

No need to write:

```text
Connection

PreparedStatement

ResultSet
```

manually.

---

#### 2. Automatic Object Mapping

```text
Java Object

↓

Database Table
```

mapping is handled automatically.

---

#### 3. Easier CRUD Operations

Methods like:

```java
save()

findAll()

findById()

deleteById()
```

are available out of the box.

---

#### 4. Better Maintainability

Code becomes:

```text
Cleaner

Smaller

More Readable
```

---

#### 5. Integration With Spring Transactions

Spring can handle transactions automatically.

---

### Key Idea

```text
Spring

↓

Integrates With JPA/Hibernate

↓

Reduces Database Boilerplate Code

↓

Makes Database Operations Easier
```

---

<a id="persistence-context-in-spring-orm"></a>

## Task 6: What is the role of @PersistenceContext in Spring ORM?

### First, What Is A Persistence Context?

A Persistence Context is a container that manages entity objects.

Think of it as:

```text
A Workspace

Used By Hibernate/JPA

To Track Entities
```

---

### Why Do We Need It?

Suppose:

```java
Employee employee =
    repository.findById(1L);
```

After fetching:

```text
Who Keeps Track
Of The Employee Object?
```

Answer:

```text
Persistence Context
```

---

### Role Of @PersistenceContext

Used to inject:

```text
EntityManager
```

into a Spring-managed class.

---

### Example

```java
@Repository
public class EmployeeRepository {

    @PersistenceContext
    private EntityManager entityManager;

}
```

---

### What Happens Here?

Spring injects an:

```text
EntityManager
```

instance automatically.

---

### What Is EntityManager?

EntityManager is the main JPA interface used to:

```text
Persist Entities

Find Entities

Update Entities

Delete Entities
```

---

### Example

```java
Employee employee =
    entityManager.find(
        Employee.class,
        1L
    );
```

---

### Internal Flow

```text
Application

↓

EntityManager

↓

Persistence Context

↓

Database
```

---

### Why Is Persistence Context Important?

It provides:

```text
Entity Tracking

Caching

Dirty Checking

Change Management
```

---

### Example

```java
Employee employee =
    entityManager.find(
        Employee.class,
        1L
    );

employee.setName("John");
```

Question:

```text
Will We Need An Explicit Update Query?
```

Often:

```text
No
```

Hibernate detects changes and updates the database automatically.

---

### Key Idea

```text
@PersistenceContext

↓

Injects EntityManager

↓

EntityManager Works With

Persistence Context

↓

Persistence Context Tracks
And Manages Entities
```

---

## Task 7: How does Spring’s transaction management improve ORM usage?

### First, What Is A Transaction?

A transaction is:

```text
A Group Of Database Operations
```

that should succeed or fail together.

---

### Example

Bank Transfer

```text
Deduct Money

↓

Add Money
```

Both operations must succeed.

---

### Problem Without Transactions

Suppose:

```text
Money Deducted

↓

Application Crashes

↓

Money Not Added
```

Data becomes inconsistent.

---

### Solution

Use:

```text
Transactions
```

---

### Spring Transaction Management

Spring provides:

```java
@Transactional
```

annotation.

---

### Example

```java
@Service
public class BankingService {

    @Transactional
    public void transferMoney() {

        withdraw();

        deposit();

    }

}
```

---

### What Happens Internally?

```text
Start Transaction

↓

withdraw()

↓

deposit()

↓

Success

↓

Commit Transaction
```

---

### If An Error Occurs

```text
Start Transaction

↓

withdraw()

↓

Exception Occurs

↓

Rollback Transaction
```

---

### Benefits For ORM

#### 1. Automatic Commit

Spring commits changes automatically.

---

#### 2. Automatic Rollback

If something fails:

```text
Rollback Entire Transaction
```

---

#### 3. Data Consistency

Prevents partial updates.

---

#### 4. Better Hibernate Integration

Hibernate works efficiently within transaction boundaries.

---

#### 5. Cleaner Code

Developers focus on:

```text
Business Logic
```

instead of transaction management code.

---

### Transaction Flow

```text
Service Method

↓

@Transactional

↓

Hibernate/JPA Operations

↓

Commit

OR

Rollback
```

---

### Real World Example

```text
Create Order

↓

Update Inventory

↓

Process Payment
```

If payment fails:

```text
Rollback Everything
```

so data remains consistent.

---
