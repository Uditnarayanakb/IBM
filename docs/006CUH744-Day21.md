## Task 1: What is the difference between Node.js and a traditional web server like Apache or Nginx?

### First, What Is Node.js?

Node.js is a JavaScript runtime environment that allows JavaScript code to run outside the browser.

Traditionally:

```text
JavaScript

↓

Browser
```

Node.js changed this to:

```text
JavaScript

↓

Server
```

---

### What Are Apache And Nginx?

Apache and Nginx are web servers.

Their primary responsibility is:

```text
Receive HTTP Requests

↓

Return HTTP Responses
```

Examples:

```text
HTML Pages

CSS Files

Images

API Requests
```

---

### Main Difference

#### Apache / Nginx

```text
Web Servers
```

Main job:

```text
Serve Requests
```

---

#### Node.js

```text
Runtime Environment
```

Main job:

```text
Execute JavaScript On Server
```

---

### Traditional Architecture

```text
Browser

↓

Apache

↓

PHP / Java / Python
```

---

### Node.js Architecture

```text
Browser

↓

Node.js

↓

Database
```

---

### Real World Example

Apache/Nginx:

```text
Receptionist
```

Accepts visitors and directs them.

Node.js:

```text
Employee
```

Performs actual work.

---

### Comparison

| Apache/Nginx | Node.js |
|-------------|----------|
| Web Server | Runtime Environment |
| Serves Requests | Executes JavaScript |
| Multi-Threaded Approaches | Event-Driven |
| Primarily Web Serving | Full Backend Development |
| Static Content Support | Application Logic Support |

---

### ASCII Representation

```text
Traditional

Browser
    |
    v
Apache
    |
    v
PHP

----------------------------------

Node.js

Browser
    |
    v
Node.js
    |
    v
```

### Key Idea

```text
Apache/Nginx
------------
Serve Requests

--------
Runs JavaScript On Server
```

## Task 2: Explain the event-driven architecture of Node.js.

### First, What Is An Event?

An event is something that happens during program execution.

Examples:

```text
Button Click

File Read Complete

API Request Received

Timer Finished

Database Response Received
```

---

### Traditional Approach

Programs often wait for operations to complete.

```text
Do Work

↓

Wait

↓

Continue
```

This wastes resources.

---

### Node.js Solution

Node.js uses:

```text
Event-Driven Architecture
```

---

### How It Works

```text

↓

↓

Continue Working

↓

Event Completes

↓

Execute Callback
```

---

### Output

Instead:

```text

↓

↓

End Printed

↓

Timer Completes

↓

Callback Executed
```

---

### Internal Flow

```text
Event

↓

Event Queue

↓

Event Loop

↓

Callback Execution
```

---

### ASCII Representation

```text

↓

↓

      |

      |

      +---- Database

      |
```

## Task 5: Why is Node.js considered non-blocking?

### First, What Does Blocking Mean?

Blocking means:

```text
Wait Until Current Task Finishes
```

Example:

```text
Read File

↓

Wait

↓

Continue
```

The application cannot do anything else during the wait.

---

### Blocking Flow

```text
Task A

↓

Wait

↓

Task B

↓

Wait

↓

Task C
```

---

### Node.js Solution

Node.js uses:

```text
Non-Blocking I/O
```

Meaning:

```text
Start Task

↓

Do Not Wait

↓

Continue Other Work

↓

Handle Result Later
```

---

### Example

#### Code

```javascript
const fs = require("fs");

console.log("Start");

fs.readFile("data.txt", "utf8", (err, data) => {
    console.log(data);
});

console.log("End");
```

---

### Output

```text
Start
End
File Content...
```

---

### Output Explanation

Node.js:

```text
Starts File Read

↓

Does Not Wait

↓

Prints End

↓

File Completes

↓

Callback Runs
```

---

### Real World Example

Imagine ordering food.

Blocking:

```text
Order Food

↓

Stand At Counter

↓

Wait 20 Minutes
```

---

Non-Blocking:

```text
Order Food

↓

Receive Token

↓

Do Other Work

↓

Collect Food When Ready
```

---

### ASCII Representation

```text
Read File

      |

      v

Background Operation

      |

      v

Continue Processing

      |

      v

Callback Executes
```

---

### Why Node.js Is Considered Non-Blocking

```text
✓ Doesn't Pause For I/O Operations

✓ Handles Many Requests Efficiently

✓ Uses Event Loop

✓ Better Resource Utilization

✓ Suitable For Real-Time Applications
```

## Task 6: What is the difference between callbacks, promises, and async/await in Node.js?

### First, Why Are We Even Learning This?

At this point we know:

```text
Node.js

↓

Single Threaded

↓

Event Driven

↓

Non-Blocking
```

From Task 5 we learned:

```text
Node.js Does Not Wait
```

for:

```text
File Reading

Database Calls

API Calls

Network Requests
```

Instead:

```text
Start Work

↓

Continue Executing Other Code

↓

Handle Result Later
```

Question:

```text
If Node.js Does Not Wait,

How Do We Receive The Result
When It Finally Arrives?
```

This is the exact problem that:

```text
Callbacks

Promises

Async/Await
```

were created to solve.

---

### The Real Problem

Suppose a database needs:

```text
2 Seconds
```

to return user information.

Question:

```text
What Should Node.js Do
During Those 2 Seconds?
```

Should it:

```text
Wait And Do Nothing?
```

No.

Node.js wants to:

```text
Continue Working
```

and process the result later.

---

### Think About It Like This

Suppose:

```text
You Ordered Food
```

Question:

```text
Should You Stand There
For 20 Minutes Doing Nothing?
```

No.

You:

```text
Place Order

↓

Do Other Work

↓

Get Food Later
```

Node.js behaves exactly the same way.

---

### So Why Do We Have 3 Different Approaches?

Because JavaScript evolved over time.

Originally:

```text
Callbacks
```

were used.

People found problems.

Then:

```text
Promises
```

were introduced.

People wanted cleaner code.

Then:

```text
Async/Await
```

was introduced.

---

### Evolution

```text
Callbacks

↓

Problems Appeared

↓

Promises

↓

Code Became Better

↓

Async/Await

↓

Code Became Easier
```

---

### Solution 1: Callbacks

### What Is A Callback?

A callback is simply:

```text
A Function That Will Execute Later
```

when some work finishes.

---

### Real Life Example

Imagine:

```text
You Give Your Phone Number
To A Restaurant
```

and say:

```text
Call Me When The Food Is Ready
```

That phone call is basically:

```text
A Callback
```

---

### Example

#### Code

```javascript
function fetchUser(callback) {

    console.log("Fetching User...");

    // Simulate database call
    setTimeout(() => {

        // Execute callback
        // after data arrives
        callback("Alice");

    }, 2000);
}

// Function passed as callback
fetchUser((user) => {

    console.log(user);

});
```

---

### Internal Flow

```text
fetchUser()

↓

Database Query Starts

↓

Node.js Continues Working

↓

Data Arrives

↓

Execute Callback

↓

Display Alice
```

---

### Output

```text
Fetching User...

Alice
```

---

### Why Were Callbacks Useful?

Because Node.js could:

```text
Start Work

↓

Continue Running

↓

Execute Callback Later
```

instead of waiting.

---

### The Big Problem

Now imagine:

```text
Get User

↓

Get Orders

↓

Get Payment

↓

Generate Invoice
```

Each step depends on the previous step.

---

### Code

```javascript
getUser(() => {

    getOrders(() => {

        getPayment(() => {

            generateInvoice(() => {

                console.log("Done");

            });

        });

    });

});
```

---

### Why Is This Bad?

Because code becomes:

```text
More Nested

More Nested

More Nested

More Nested
```

---

### Visual Representation

```text
getUser()

  |

  v

getOrders()

   |

   v

getPayment()

    |

    v

generateInvoice()

     |

     v

     Done
```

---

### This Problem Is Called

```text
Callback Hell
```

---

### Callback Hell Problems

```text
Hard To Read

Hard To Debug

Hard To Maintain

Too Much Nesting
```

---

### Solution 2: Promises

### Why Were Promises Created?

Simple.

To solve:

```text
Callback Hell
```

---

### What Is A Promise?

A Promise is just:

```text
A Result That Will Arrive Later
```

Think of it like:

```text
A Food Token
```

You don't have food yet.

But you know:

```text
Food Will Arrive Later
```

---

### Example

#### Code

```javascript
function fetchUser() {

    // Return a Promise

    return new Promise((resolve) => {

        console.log("Fetching User...");

        setTimeout(() => {

            // Send result
            resolve("Alice");

        }, 2000);

    });
}

fetchUser()

    .then((user) => {

        // Executes when promise resolves
        console.log(user);

    });
```

---

### Internal Flow

```text
Create Promise

↓

Start Work

↓

Continue Running

↓

Data Arrives

↓

Promise Resolved

↓

then() Executes
```

---

### Output

```text
Fetching User...

Alice
```

---

### Why Is This Better?

Instead of:

```javascript
getUser(() => {

    getOrders(() => {

        getPayment(() => {

            generateInvoice();

        });

    });

});
```

we can do:

```javascript
getUser()
    .then(getOrders)
    .then(getPayment)
    .then(generateInvoice);
```

---

### Promise Flow

```text
Get User

↓

Get Orders

↓

Get Payment

↓

Generate Invoice
```

Cleaner.

---

### Benefits

```text
Less Nesting

Cleaner Code

Better Error Handling

More Readable
```

---

### Solution 3: Async/Await

### Why Was Async/Await Introduced?

Because some developers still looked at:

```javascript
.then()
.then()
.then()
```

and said:

```text
Can This Be Simpler?
```

Answer:

```text
Yes
```

---

### What Is Async/Await?

It is simply:

```text
A Cleaner Way To Write Promises
```

Important:

```text
Async/Await Internally Uses Promises
```

It is not a different technology.

Only a different syntax.

---

### Example

#### Code

```javascript
function fetchUser() {

    return new Promise((resolve) => {

        setTimeout(() => {

            resolve("Alice");

        }, 2000);

    });
}

async function displayUser() {

    // Wait for Promise result
    const user =
        await fetchUser();

    console.log(user);
}

displayUser();
```

---

### Internal Flow

```text
Call Promise

↓

Wait For Result

↓

Result Arrives

↓

Store In Variable

↓

Display Output
```

---

### Output

```text
Alice
```

---

### Why Is It Easier?

#### Promise Version

```javascript
fetchUser()
    .then((user) => {

        console.log(user);

    });
```

---

#### Async/Await Version

```javascript
const user =
    await fetchUser();

console.log(user);
```

Looks much closer to normal code.

---

### Real Life Comparison

#### Callback

```text
Call Me
When Food Is Ready
```

---

#### Promise

```text
Take This Token

Food Will Arrive Later
```

---

#### Async/Await

```text
I'll Wait For The Food
Then Continue
```

---

### So Which One Should We Use Today?

### Old Projects

You may see:

```text
Callbacks
```

---

### Most Applications

You will see:

```text
Promises
```

---

### Modern Node.js

Preferred approach:

```text
Async/Await
```

because it is easiest to read.

---

### Final Mental Model

Task 5 taught:

```text
Node.js Does Not Wait
```

Question:

```text
Then How Do We Handle Results
That Arrive Later?
```

Answer:

```text
Callbacks

↓

Promises

↓

Async/Await
```

These are simply 3 generations of solving the same problem.

---

### Comparison Table

| Callback | Promise | Async/Await |
|-----------|-----------|-------------|
| Old Approach | Improved Approach | Modern Approach |
| Uses Callback Functions | Uses Promise Objects | Uses Promises Internally |
| Callback Hell Possible | No Callback Hell | No Callback Hell |

---

### ASCII Representation

```text
Node.js

↓

Non-Blocking

↓

Result Arrives Later

↓

Need To Handle Result

      |

      +---- Callback

      |

      +---- Promise

      |
```

### Key Idea

```text

```

Modules allow us to:

```text

Reuse It Anywhere
```

---

### What Is CommonJS?

CommonJS is the traditional module system used by Node.js.

It uses:

```javascript
require()
```

to import modules.

and:

```javascript
module.exports
```

or

```javascript
exports
```

to export modules.

---

### CommonJS Flow

```text

↓

↓
```

### Step 1: Create math.js

```javascript
}

function multiply(a, b) {
    return a * b;
}

function divide(a, b) {
    return a / b;
}

// Export all functions
module.exports = {
    add,
    subtract,
    multiply,
    divide
};
```

## Task 6: What is Mongoose? What are the key features? Why do we use it?

### First, What Problem Does Mongoose Solve?

Suppose we are using:

```text
Node.js

↓

MongoDB
```

Question:

```text
How Does Node.js Talk To MongoDB?
```

One option is:

```text
MongoDB Native Driver
```

But writing validation, data structure checks, and database-related logic manually can become difficult. Mongoose was created to make working with MongoDB easier in Node.js applications. 

---

### What Is Mongoose?

Mongoose is an:

```text
ODM
(Object Data Modeling)
```

library for:

```text
Node.js

+

MongoDB
```

It provides a schema-based way to model and manage application data. 

---

### Simple Definition

```text
Mongoose

↓

Node.js Application

↓

MongoDB Database
```

Mongoose sits between Node.js and MongoDB and provides a structured way to work with data. 

---

### Without Mongoose

```text
Node.js

↓

MongoDB Driver

↓

MongoDB
```

You write more database-related code yourself.

---

### With Mongoose

```text
Node.js

↓

Mongoose

↓

MongoDB
```

Mongoose handles many common tasks automatically. 

---

### What Is A Schema?

A schema defines:

```text
What Data Should Look Like
```

Example:

```javascript
const userSchema =
{
    name: String,
    age: Number,
    email: String
};
```

This tells Mongoose:

```text
User Must Have

Name

Age

Email
```



---

### Example

#### Code

```javascript
const mongoose =
    require("mongoose");

// Define schema
const userSchema =
    new mongoose.Schema({

        name: String,
        age: Number

    });

// Create model
const User =
    mongoose.model(
        "User",
        userSchema
    );
```

---

### What Happens Internally?

```text
Schema Created

↓

Model Created

↓

Model Connected To Collection

↓

Database Operations Become Easier
```

---

### Key Features Of Mongoose

### 1. Schema-Based Data Modeling

Mongoose allows developers to define a structure for documents using schemas. 

```text
Consistent Data Structure

↓

Better Readability

↓

Better Maintenance
```

---

### 2. Data Validation

Mongoose can validate data before saving it to MongoDB. 

Example:

```javascript
age: Number
```

If someone tries:

```text
age = "hello"
```

validation can prevent invalid data from being stored.

---

### 3. Models

Schemas are converted into Models.

Models allow:

```text
Create

Read

Update

Delete
```

operations on MongoDB collections. 

---

### 4. Query Building

Mongoose provides an easier API for querying data. 

Example:

```javascript
User.find();
```

instead of writing lower-level database operations.

---

### 5. Middleware / Hooks

Mongoose supports:

```text
Pre Hooks

Post Hooks
```

which allow custom logic before or after operations. 

Example:

```text
Before Save

↓

Validate Data

↓

Save Document
```

---

### 6. Relationships Using Populate

Mongoose can connect documents from different collections using:

```javascript
populate()
```

similar to joins in relational databases. 

---

### Why Do We Use Mongoose?

### Without Mongoose

### With Mongoose
