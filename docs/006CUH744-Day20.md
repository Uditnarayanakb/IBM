## Task 1: What do you understand about integration testing?

### First, What Is Integration Testing?

Before understanding Integration Testing, let's understand why it was introduced.

After Unit Testing we know:

```text
OrderService Works

PaymentService Works

UserService Works
```

Question:

```text
Do they work together?
```

Unit Testing cannot answer this.

Integration Testing was introduced to verify that multiple components work correctly as a group.

---

### Traditional Situation

Imagine:

```text
Controller

↓

Service

↓

Repository

↓

Database
```

Unit Tests verify individual pieces.

Integration Tests verify the complete flow.

---

### Definition

Integration Testing is a testing technique used to verify communication and interaction between multiple components of an application.

---

### Real World Example

```text
ATM Machine
```

Testing only:

```text
Card Reader
```

is Unit Testing.

Testing:

```text
Card Reader
↓

Bank Server
↓

Database
↓

Cash Dispenser
```

together is Integration Testing.

---

### ASCII Representation

```text
Unit Testing

Controller

Service

Repository

Tested Individually

----------------------------------

Integration Testing

Controller
    |
    v
Service
    |
    v
Repository
    |
    v
Database

All Components Together
```

---

### Key Idea

```text
Unit Test

"Does this component work?"

----------------------------------

Integration Test

"Do these components work together?"
```

## Task 3: Can you write an integration test for your existing code?
```
For example 🎉
java
@SpringBootTest
@AutoConfigureMockMvc
class UserControllerIT {

    @Autowired
    private MockMvc mockMvc;

    @Test
    void testGetUser() throws Exception {
        mockMvc.perform(get("/users/1"))
               .andExpect(status().isOk())
               .andExpect(jsonPath("$.name").value("Alice"));
    }
}

```


### Before Writing Code

In Unit Testing:

```java
@MockBean
```

or

```java
mock()
```

is commonly used.

But Integration Testing is different.

Question:

```text
Do Real Components Work Together?
```

To answer that, we use:

```java
@SpringBootTest
```

which loads the complete Spring Application Context.

---

### Example

#### Code

```java
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.servlet.AutoConfigureMockMvc;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.test.web.servlet.MockMvc;

import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

@SpringBootTest
@AutoConfigureMockMvc
class UserControllerIT {

    @Autowired
    private MockMvc mockMvc;

    @Test
    void testGetUser() throws Exception {

        mockMvc.perform(get("/users/1"))
               .andExpect(status().isOk())
               .andExpect(jsonPath("$.name").value("Alice"));
    }
}
```

---

### Understanding Line By Line

#### Step 1

```java
@SpringBootTest
```

Loads the complete Spring Boot Application Context.

---

#### Step 2

```java
@AutoConfigureMockMvc
```

Configures MockMvc automatically.

Allows endpoint testing without starting a real web server.

---

#### Step 3

```java
@Autowired
private MockMvc mockMvc;
```

Injects the MockMvc object.

---

#### Step 4

```java
mockMvc.perform(get("/users/1"))
```

Sends:

```http
GET /users/1
```

to the application.

---

#### Step 5

```java
.andExpect(status().isOk())
```

Verifies:

```http
200 OK
```

is returned.

---

#### Step 6

```java
.andExpect(jsonPath("$.name").value("Alice"))
```

Verifies:

```json
{
  "name": "Alice"
}
```

is returned in the response body.

---

### Output

```text
Test Passed
```

---

### Output Explanation

Spring executes:

```text
Controller
↓

Service
↓

Repository
↓

Database
```

and verifies the response.

If any layer fails, the test fails.

---

### Expected Flow

```text

        |

        v

UserController

        |

        v

UserService

        |

        v

UserRepository

        |

        v

        |

        v

```

---

### Why Is This An Integration Test?

Because:

```text
Controller

↓

Service

↓

Repository

↓

Database
```

are working together.

No isolated business logic testing.

Real application collaboration is being verified.

---

### Difference Between Unit Testing And Integration Testing

| Unit Testing | Integration Testing |
|-------------|--------------------|
| Tests Single Component | Tests Multiple Components |
| Uses Mocks | Uses Real Components |
| Fast | Slower |
| Focuses On Logic | Focuses On Component Interaction |

## Task 4: What are Testcontainers?

### First, What Are Testcontainers?

Before understanding Testcontainers, let's understand a common problem in Integration Testing.

Suppose your application uses:

```text
PostgreSQL

MySQL

Redis

Kafka
```

Your Integration Tests require these services.

Question:

```text
Where will they run?
```

Developers traditionally had two choices:

```text
Install Everything Manually

OR

Use Shared Test Servers
```

Both approaches created problems.

---

### Traditional Problems

#### Manual Installation

Every developer machine needs:

```text
Database

Message Broker

Cache

Configuration
```

Problems:

```text
Version Differences

Setup Issues

Environment Conflicts
```

---

#### Shared Testing Environment

```text
Developer A

Developer B

Developer C
```

all use the same test database.

Problems:

```text
Data Conflicts

Unstable Tests

Dependency On Shared Infrastructure
```

---

### Java Solution

To solve these problems, developers created:

```text
Testcontainers
```

Testcontainers is a Java library that uses Docker containers during testing. It creates temporary, lightweight instances of databases, message brokers, and other services required by tests. 

---

### Definition

Testcontainers is a testing library that starts real Docker containers during test execution and automatically removes them after the tests finish. 

---

### Why Is It Useful?

Instead of using:

```text
Mock Database
```

we can use:

```text
Real PostgreSQL Container

Real MySQL Container

Real Redis Container

Real Kafka Container
```

during testing. 

---

### Example Scenario

Application:

```text
Order Service

      |

      v

PostgreSQL Database
```

When the Integration Test starts:

```text
Testcontainers

      |

      v

Starts PostgreSQL Container

      |

      v

Runs Tests

      |

      v

Deletes Container
```

---

### Basic Example

#### Code

```java
import org.junit.jupiter.api.Test;
import org.testcontainers.containers.PostgreSQLContainer;

class DatabaseTest {

    @Test
    void testDatabaseConnection() {

        try (PostgreSQLContainer<?> postgres =
                 new PostgreSQLContainer<>("postgres:16")) {

            postgres.start();

            System.out.println(
                postgres.getJdbcUrl()
            );
        }
    }
}
```

---

### Output

```text
jdbc:postgresql://localhost:xxxxx/test
```

---

### Output Explanation

Testcontainers:

```text
Downloads Container

↓

Starts PostgreSQL

↓

Provides JDBC URL

↓

Runs Test

↓

Deletes Container
```

---

### Real World Example

Imagine testing:

```text
Spring Boot Application

↓

PostgreSQL

↓

Redis

↓

Kafka
```

Instead of manually installing everything, Testcontainers creates them automatically for every test execution. 

---

### ASCII Representation

```text

       |

       v

Testcontainers

       |

       +---- PostgreSQL

       |

       +---- Redis

       |

       +---- Kafka

       |
```


## Task 6: Can you write a piece of code for your existing application to see how Testcontainers works?

### What Are We Testing?

Suppose our Spring Boot application contains:

```text

```

---

### Example

#### Code

```java
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.testcontainers.containers.PostgreSQLContainer;
import org.testcontainers.junit.jupiter.Container;
import org.testcontainers.junit.jupiter.Testcontainers;

import static org.junit.jupiter.api.Assertions.assertEquals;

@Testcontainers
class UserRepositoryIT {

    @Container
    static PostgreSQLContainer<?> postgres =
        new PostgreSQLContainer<>("postgres:15");

    @Autowired
    private UserRepository userRepository;

    @Test
    void testSaveUser() {

        User user = new User("Alice");

        userRepository.save(user);

        assertEquals(
            "Alice",
            userRepository
                .findById(user.getId())
                .get()
                .getName()
        );
    }
}
```

---

#### Step 1

```java
@Testcontainers
```

Tells JUnit that this test class uses Testcontainers.

Testcontainers will manage container startup and shutdown automatically. 

---

#### Step 2

```java
@Container
```

Marks the PostgreSQL container that should be managed during test execution.

---

#### Step 3

```java
new PostgreSQLContainer<>("postgres:15")
```

Creates a real PostgreSQL Docker container using:

```text
postgres:15
```

image.

---

#### Step 4

```java
@Autowired
private UserRepository userRepository;
```

Injects the Spring Data Repository.

---

#### Step 5

```java
User user = new User("Alice");
```

Creates a User object.

---

#### Step 6

```java
userRepository.save(user);
```

Stores the user inside the real PostgreSQL database container.

---

#### Step 7

```java
userRepository.findById(user.getId())
```

Reads the user from the same database.

---

#### Step 8

```java

    "Alice",
    ...
);
```

Verifies that the stored value and retrieved value match.

## Task 7: What is Code Coverage?

### First, What Is Code Coverage?

We have already learned:

```text
Unit Testing

Integration Testing

Testcontainers
```

Question:

```text
How do we know whether our tests actually test enough code?
```

Suppose our application contains:

```java
public int calculateBonus(int salary) {

    if (salary > 50000) {
        return 10000;
    }

    return 5000;
}
```

Now imagine our test only checks:

```java
calculateBonus(60000);
```

Question:

```text
Did we test everything?
```

Answer:

```text
No
```

The:

```java
return 5000;
```

path was never executed.

This is where Code Coverage becomes useful.

---

### Definition

Code Coverage is a software testing metric that measures how much of the application's source code is executed while running tests. It helps identify code that has not been tested. 

---

### Simple Example

#### Code

```java
public int findMax(int a, int b) {

    if (a > b) {
        return a;
    }

    return b;
}
```

---

### Test Case

```java
findMax(10, 5);
```

Only:

```java
return a;
```

is executed.

The:

```java
return b;
```

path is not executed.

Therefore:

```text
Coverage < 100%
```

---

### Coverage Concept

```text
Application Code

      |

      +---- Executed By Tests

      |

      +---- Not Executed By Tests

Code Coverage Measures This Difference
```

---

### Common Types Of Code Coverage

#### 1. Line Coverage

Question:

```text
How many lines were executed?
```

---

#### 2. Branch Coverage

Question:

```text
Were both TRUE and FALSE paths executed?
```

Example:

```java
if(age >= 18)
```

Need to test:

```text
TRUE

FALSE
```

paths. 

---

#### 3. Function Coverage

Question:

```text
Was every method called?
```

Example:

```java
saveUser()

deleteUser()

updateUser()
```

All methods should execute at least once. 

---

### Example

Suppose:

```text
100 Lines Of Code
```

exist in an application.

Tests execute:

```text
80 Lines
```

Coverage:

```text
80%
```

Coverage Formula:

```text
(Number Of Executed Code Elements / Total Code Elements)
× 100
```



---

### Real World Example

Imagine inspecting a building.

You check:

```text
Ground Floor

First Floor

Second Floor
```

but never inspect:

```text
Third Floor
```

Can you say the entire building has been inspected?

```text
No
```

Code Coverage works similarly.

If some code never executes during testing:

```text
It Has Not Been Verified
```

---

### ASCII Representation

```text
Application Code

      |

      +---- Tested

      |

      +---- Not Tested

               |

               v

        Coverage Report

               |

               v

          80%
```

---

### Important Note

```text
100% Coverage
```

does NOT guarantee:

```text
100% Bug-Free Application
```

It only means:

```text
All Code Was Executed
```

during testing. 

---

### Key Idea

```text
Code Coverage Answers

"How much code was tested?"
```

```text
Did the tests execute all the code?
```

Answer:

```text
We Don't Know
```

Without Code Coverage, developers cannot easily identify untested sections of the application. 

---

### Problem Without Code Coverage

Developers may assume:

```text

Therefore Everything Is Tested
```

```text

```

The remaining code never ran during testing.

#### 1. Find Untested Code

```text

Which Code Never Executed
```

Example:

```java

```

```text

False Path Not Tested
```

Now we know what test to add. 

---

#### 3. Reduce Production Bugs

Untested code often becomes:

```text
Hidden Risk
```

More testing generally means:

```text
Higher Confidence
```

in the application. 

---

#### 4. Support CI/CD Pipelines

Many companies enforce rules like:

```text

Minimum 85% Coverage
```

before deployment. Coverage metrics are commonly integrated into modern CI/CD processes. 

---

#### 5. Increase Developer Confidence

Before release:

```text
Developer

      |

      v

      |

      v

More Confidence
```

because the team knows most important code paths were executed.

## Task 10: What is Redux used for?

### First, What Is Redux?

Before understanding Redux, let's first understand a common problem in frontend applications.

Suppose we have:

```text
Login Component

Profile Component

Cart Component

Navbar Component
```

All these components need access to:

```text
User Information
```

Question:

```text
Where should we store this data?
```

If every component stores its own copy:

```text
Data Duplication

Inconsistent State

Difficult Maintenance
```

can occur.

To solve this problem, Redux was introduced.

---

### Definition

Redux is a state management library used to store and manage application data in a centralized location called a Store.

---

### What Is State?

State simply means:

```text
Data Used By The Application
```

Examples:

```text
Logged In User

Shopping Cart

Theme

Notifications

Language Preference
```

---

### Redux Solution

Instead of:

```text
Component A Stores Data

Component B Stores Data

Component C Stores Data
```

Redux uses:

```text
One Central Store
```

for the entire application.

---

### Why Redux?

Redux helps:

```text
Share Data Across Components

Maintain Predictable State

Avoid Prop Drilling

Centralize Data Management
```

---

### Real World Example

Imagine a bank.

Instead of every employee maintaining their own customer records:

```text
Employee A Record

Employee B Record

Employee C Record
```

they use:

```text
Central Database
```

Redux works similarly.

---

### ASCII Representation

```text
Without Redux

Component A

Component B

Component C

Each Managing Data

----------------------------------

With Redux

Component A ----|
                |
Component B ----|---- Redux Store
                |
Component C ----|
```

---

### Key Idea

```text
Redux

=

Centralized State Management
```

## Task 12: What is useSelector used for?

### First, What Is useSelector?

When using Redux, data is stored inside:

```text
Redux Store
```

Question:

```text
How do React Components read that data?
```

Answer:

```text
useSelector()
```

---

### Definition

useSelector is a React Redux Hook used to read data from the Redux Store.

---

### Example Store

```text
Store

↓

user

↓

name = Alice
```

A component can access this data using:

```javascript
useSelector()
```

---

### Code

```javascript
import { useSelector } from "react-redux";

function Profile() {

    const user = useSelector(
        state => state.user
    );

    return (
        <h1>{user.name}</h1>
    );
}
```

---

### Understanding The Code

#### Step 1

```javascript
useSelector(...)
```

connects to Redux Store.

---

#### Step 2

```javascript
state.user
```

retrieves user information.

---

#### Step 3

```javascript
user.name
```

displays user name.

---

### Output

```text
Alice
```

---

### Output Explanation

Redux Store contains:

```text
user

↓

Alice
```

useSelector reads the state and displays it.

---

### Real World Example

Shopping Cart

Redux Store:

```text
cartItems = 5
```

Navbar:

```javascript
const count =
    useSelector(
        state => state.cartItems
    );
```

Display:

```text
Cart (5)
```

---

### ASCII Representation

```text
Redux Store

       |

       v

    State

       |

       v

 useSelector()

       |

       v

 React Component
```

---

### Key Idea

```text
useSelector

=

Read Data From Redux Store
```
