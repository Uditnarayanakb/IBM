TASK 1: WHAT IS DATA BINDING?
======================================================================

EXPLANATION:
------------

Data Binding is the process of connecting data between the User
Interface (UI) and the application logic.

It helps display data on the screen and also allows the application
to receive user input.

In React, data binding is achieved using:

✓ Props

✓ State

✓ Event Handling

Data can flow from the component to the UI or from the UI back to the
component.

======================================================================
EXAMPLE
======================================================================

function App() {

   const name = "John";

   return (

      <h1>{name}</h1>

   );

}

          To User

TASK 2: WHAT DO YOU UNDERSTAND BY ONE WAY DATA BINDING AND TWO WAY
DATA BINDING?
======================================================================

EXPLANATION:
------------

One-Way Data Binding means data flows in only one direction.

Two-Way Data Binding means data flows in both directions between
the UI and the component.

======================================================================
ONE-WAY DATA BINDING
======================================================================

Data flows:

Component --> UI

Changes in the component automatically update the UI.

CODE:
------

function App() {

   const name = "John";

   return (

      <h1>{name}</h1>

   );

}

======================================================================
ASCII REPRESENTATION
======================================================================

   Component Data
         |
         v

         UI

======================================================================
OUTPUT
======================================================================

======================================================================
TWO-WAY DATA BINDING
======================================================================

Data flows:

Component <--> UI

React does not provide automatic two-way binding like Angular.

We achieve it using:

✓ useState()

✓ onChange()

CODE:
------

import { useState } from 'react';

function App() {

   const [name, setName] = useState("");

   return (

      <input
         value={name}
         onChange={(e) => setName(e.target.value)}
      />

   );

}

TASK 4: WHAT IS THE STATE IN REACT?
======================================================================

EXPLANATION:
------------

State is a built-in React object used to store and manage data that can
change over time.

When state changes, React automatically re-renders the component and
updates the UI.

State is mutable, meaning its value can be updated.

React commonly uses the useState() Hook to manage state.

CODE:
------

import { useState } from 'react';

function Counter() {

   const [count, setCount] = useState(0);

   return (

      <div>

         <h1>{count}</h1>

         <button
            onClick={() => setCount(count + 1)}
         >
            Increment
         </button>

      </div>

   );

}

TASK 5: CAN YOU EXPLAIN SPA?
======================================================================

EXPLANATION:
------------

SPA stands for Single Page Application.

A Single Page Application loads only one HTML page initially and updates
content dynamically without refreshing the entire page.

React is primarily used to build SPAs.

Instead of loading a new page from the server every time, React updates
only the required part of the UI.

TASK 7: WHAT IS VIRTUAL DOM?
======================================================================

EXPLANATION:
------------

Virtual DOM is a lightweight copy of the Real DOM maintained by React.

When data changes:

1. React creates a new Virtual DOM.
2. React compares it with the previous Virtual DOM.
3. React identifies the changed elements.
4. React updates only those elements in the Real DOM.

This process is called Reconciliation.

ADVANTAGES:
-----------

✓ Faster Rendering

✓ Better Performance

✓ Fewer DOM Manipulations

✓ Improved User Experience

ASCII REPRESENTATION:
---------------------

             State Change
                   |
                   v

                   |
                   v

             Compare Old
             And New DOM

                   |
                   v

            Find Changes

                   |
                   v

              Real DOM
              Update

FLOW:
------

State Change

     |
     v

Virtual DOM

     |
     v

Diffing

     |
     v

Update Real DOM

Props stands for Properties.

Props are used to pass data from a Parent Component to a Child

function App() {

======================================================================
PROP DRILLING
======================================================================

EXPLANATION:
------------

Prop Drilling occurs when props are passed through multiple components
just to reach a deeply nested component.

CODE:
------

function App() {

   return <Parent user="John" />;

}

function Parent({ user }) {

   return <Child user={user} />;

}

function Child({ user }) {

   return <GrandChild user={user} />;

}

function GrandChild({ user }) {

   return <h1>{user}</h1>;

}

ASCII REPRESENTATION:
---------------------

 |

 |
 v

Child

 |
 v

TASK 13: WHAT IS REACT REDUX ARCHITECTURE?
EXPLAIN IN DETAIL.
======================================================================

EXPLANATION:
------------

Redux is a state management library used with React applications.

Redux helps manage application-wide (global) state in a centralized
location called the Store.

Instead of passing data through multiple components (Prop Drilling),
Redux allows components to access shared state directly.

======================================================================
WHY REDUX?
======================================================================

Without Redux:

App

 |
 v

 |
 v

Child

 |
 v

GrandChild

 |
 v

(Prop Drilling)

--------------------------------------------------

With Redux:

All Components

       |

       v

 Shared Data

======================================================================
MAIN COMPONENTS OF REDUX
======================================================================

1. Store

2. Action

3. Reducer

4. Dispatch

5. Selector

======================================================================
1. STORE
======================================================================

The Store is the central location where application state is stored.

Example:

User Data

Cart Data

Employee Data

Theme Settings

======================================================================
2. ACTION
======================================================================

Action describes what happened.

Example:
---------

{
   type: "INCREMENT"
}

{
   type: "ADD_EMPLOYEE"
}

======================================================================
3. REDUCER
======================================================================

Reducer contains the logic that updates the state.

CODE:
------

function counterReducer(
   state = 0,
   action
) {

   switch(action.type) {

      case "INCREMENT":

         return state + 1;

      default:

         return state;

   }

}

======================================================================
4. DISPATCH
======================================================================

Dispatch sends actions to Redux.

CODE:
------

dispatch({
   type: "INCREMENT"
});

======================================================================
5. SELECTOR
======================================================================

Selectors are used to read data from the store.

CODE:
------

const count = useSelector(
   state => state.count
);
